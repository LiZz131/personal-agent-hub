# 提交检查点

用户通过飞书里的「主控 agent」管理所有项目。检查点会发到飞书，产物作为附件一起发给用户；用户回复后，主控把结论用跨会话消息送回**本会话**。

## 什么时候用
- 阶段成果需要用户验收：剧本、文案、渲染好的视频、实验结论、论文段落、可以交付的版本。
- 需要用户做方向性决定：方案 A/B 取舍、要不要换路线、实验结论怎么解读。
- 需要改 Notion 里的任务状态（完成、待验证）：把建议的变更写进 `--notion`，用户回复「通过」就同时批准。

不要用于小问题（「要不要继续」「要不要提交」），这些直接在对话里问。

## 怎么提交
在当前项目目录里运行（路径固定，不依赖当前项目的 Python 环境）：

```
{{HUB}}\.venv\Scripts\python.exe -I {{HUB}}\scripts\checkpoint.py --title "<≤20 字标题>" --question "<要用户决定或验收什么；有选项就列出选项和各自代价>" --summary "<做了什么、关键结果、证据（提交、指标、文件）>" --artifact <产物文件> [--artifact <更多文件>] [--notion "<建议的 Notion 变更：哪个任务 / 检查点 / 实验记录，改成什么>"]
```

- `--artifact` 给要用户直接看的文件：文档、脚本、图片、视频（单个 ≤ 30 MB，超过的会注明未附上）。
- 文字要完整、具体，用户在手机上只看这张卡片就能做决定。

## 提交之后
1. **结束本轮**，不要继续依赖这个决定的工作；与它无关、确定要做的事可以先做完再结束。
2. 之后会收到 `<cross-session-message from-name="…">`，内容以「主控转达（来自飞书）」开头，这就是用户的决定：「通过」→ 继续下一步；「打回 + 意见」→ 按意见修改后再提交新的检查点。
3. 如果用户直接在终端里回答了，按终端里的回答执行即可，主控会自动把检查点标为已处理。
