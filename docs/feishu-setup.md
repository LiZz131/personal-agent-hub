# 飞书接入操作文档（方案 B：自建应用 + 长连接）

目标：建一个只有你自己能用的飞书机器人。本机守护进程通过**长连接**收发消息，不需要公网 IP 或内网穿透。

预计用时 30–40 分钟。所有命令都在 `<hub>` 下执行（PowerShell）。

---

## 第 0 步：前提确认

- **你需要能发布自建应用**。打开 飞书 → 头像 → 「管理后台」，能进去说明你是管理员。
  - 进不去的话，有两种办法：
    - 找企业管理员审批应用（第 6 步会提交审批）。
    - 自己新建一个个人用的飞书团队：飞书 → 头像 → 「创建/加入团队」→ 创建，免费。之后在这个团队下操作，你就是管理员。
  - 建议用个人团队，避免把个人知识库挂在学校或公司的组织下。
- Python 环境：仓库内的 `.venv` 已经建好，依赖装好了。不要用全局 `python`。

---

## 第 1 步：创建应用

1. 浏览器打开 <https://open.feishu.cn/app>，用第 0 步确定的那个团队账号登录。
   - 右上角可以切换团队，确认选中的是正确的团队。
2. 点「创建企业自建应用」：
   - 名称：`Personal Agent`（随意）
   - 描述：`个人知识与项目助手`
   - 图标：随意
3. 创建后进入应用详情页。

## 第 2 步：拿到凭证，填进 .env

1. 左侧菜单「凭证与基础信息」，复制 **App ID**（`cli_` 开头）和 **App Secret**。
2. 在仓库根目录执行：
   ```powershell
   copy .env.example .env
   notepad .env
   ```
3. 填两行，等号两边不要有空格或引号：
   ```
   FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
   FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
4. 验证：
   ```powershell
   .venv\Scripts\python -I scripts\feishu_check.py token
   ```
   看到 `✅ App ID / Secret 正确` 再往下走。

> App Secret 相当于密码。`.env` 已经在 `.gitignore` 里，也对 Claude Code 禁读。不要把它发到任何聊天里，包括发给我。

## 第 3 步：添加机器人能力

左侧「添加应用能力」→ 找到「机器人」→ 点「添加」。

## 第 4 步：开通权限

左侧「权限管理」→「开通权限」。在搜索框里**按权限标识搜索**（中文名称可能随版本略有变化，标识不会变），逐个勾选：

| 权限标识 | 中文名（参考） | 用途 |
|---|---|---|
| `im:message` | 获取与发送单聊、群组消息 | 基础收发 |
| `im:message.p2p_msg:readonly` | 读取用户发给机器人的单聊消息 | 收你的私聊 |
| `im:message.group_at_msg:readonly` | 接收群聊中 @机器人消息事件 | 以后在项目群里 @它 |
| `im:message:send_as_bot` | 以应用的身份发消息 | 推送简报、回复 |
| `im:resource` | 获取与上传图片或文件资源 | 下载你发来的 PDF |

勾选后点「确认开通」。**暂时不要开其他权限**，需要时再加。

## 第 5 步：配置事件订阅（长连接）

这一步要求**本地长连接客户端在线**，否则后台无法保存。

1. 开一个 PowerShell 窗口，运行下面的命令并保持窗口开着：
   ```powershell
   .venv\Scripts\python -I scripts\feishu_check.py listen
   ```
   日志里出现 `connected to wss://...` 就表示已连上。
2. 回到开发者后台，左侧「事件与回调」→「事件配置」：
   - 「订阅方式」点编辑 → 选 **使用长连接接收事件** → 保存。
   - 提示客户端未连接的话，检查第 1 小步的窗口是否还在运行。
   - 点「添加事件」→ 搜索 `im.message.receive_v1`（接收消息 v2.0）→ 添加。
3. 同一页切到「回调配置」标签，这一项是为以后的审批卡片准备的：
   - 「订阅方式」同样选 **使用长连接接收回调** → 保存。
   - 「添加回调」→ `card.action.trigger`（卡片回传交互）→ 添加。

## 第 6 步：发布版本

权限和事件都要**发布版本后才生效**。

1. 左侧「版本管理与发布」→「创建版本」：
   - 应用版本号：`1.0.0`
   - 更新说明：`初始版本`
   - **可用范围**：点编辑，**只选你自己**。
2. 保存 →「申请线上发布」。
3. 审批：
   - 如果你是管理员，通常自动通过。没有自动通过的话，去 飞书管理后台 →「工作台」→「应用审核」里通过。
   - 如果你不是管理员，等管理员审批。

以后每次改权限或事件，都要重复这一步（版本号递增，如 1.0.1）。

## 第 7 步：拿到你的 open_id

1. 确认第 5 步的 `listen` 窗口还在运行。如果已经关了，重新运行。
2. 打开飞书客户端 → 搜索框搜 `Personal Agent` → 进入和机器人的单聊 → 随便发一句话，比如 `hi`。
3. 预期结果：
   - 终端打印 `发送者 open_id = ou_xxxxxxxx`。
   - 飞书里机器人回复「自检成功 ✅」，并附上你的 open_id。
4. 把它填进 `.env`：
   ```
   FEISHU_OWNER_OPEN_ID=ou_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
5. 回到 `listen` 窗口，按 `Ctrl+C` 退出。

> open_id 是这个用户在**这个应用下**的唯一标识。换一个应用后会变，所以必须用这个应用来获取。

## 第 8 步：验证主动推送

```powershell
.venv\Scripts\python -I scripts\feishu_check.py send
```
飞书里收到「Personal Agent 主动推送测试 ✅」，就全部完成了。

## 常见问题

| 现象 | 处理 |
|---|---|
| `token` 报 `app_id or app_secret invalid` | 重新复制，注意首尾空格；确认 `FEISHU_DOMAIN=feishu` |
| 后台保存长连接时提示未检测到连接 | `listen` 没在运行或已断开；重新运行，等出现 connected 后再保存 |
| 飞书里搜不到机器人 | 版本没发布或审批没通过；可用范围里没有包含你 |
| 发消息后终端没反应 | 没添加 `im.message.receive_v1` 事件，或添加后没重新发布版本 |
| 能收到消息但回复失败，报 `code=230xxx` 或权限错误 | 缺 `im:message:send_as_bot`，开通后重新发布版本 |
| 公司或学校网络下连不上 | 长连接走 `wss://` 出站 443 端口；换网络试试，或检查代理 |
