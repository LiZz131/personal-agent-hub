# 每日早报

**只读**：不写 Notion、不改 state、不给工作会话发消息。需要改的东西只写成「建议」。

## 1. 本地数据
运行 `.venv/Scripts/python -I scripts/brief_data.py`（默认过去 24 小时；我问「这周」时加 `--hours 168`）。
它给出：各项目「待我决定」、动态、需要我处理的会话（blocked / waiting）、分诊异常。
- **「等你拍板」只来自「待我决定」**。动态是历史记录：里面的「等你…」「待你确认」可能早已处理（标签后面会注明「已处理」），不要列进「等你拍板」。

## 2. Notion（只读）
用 `notion-query-data-sources` 查**任务**库（id 是 `config/hub.yaml` 的 `notion.tasks`；未配置就跳过本节）（字段见 `docs/design/notion-structure.md`）：
- 状态为 下一步 / 进行中 / 待验证 / 已阻塞 的任务：标题、所属项目、优先级、截止日期、下一步行动、完成标准；
- 截止日期在今天起 3 天内（含已过期未完成）的任务。
查询失败时改用 `notion-search` 兜底，并在早报末尾注明「Notion 查询不完整」。不要因为 Notion 出错而不发早报。

## 3. 写早报
手机上看，简洁、具体，结论先行。没有内容的小节直接省略。

```markdown
# ☀️ 早报 MM-DD 周X

## 🧭 等你拍板（N）
- #标签 一句话：要你决定什么（来自「待我决定」）

## 🎯 今天建议推进
1. **任务名**（项目）— 为什么是今天：截止 / 待验证需要你 / 阻塞了别人 / 昨天的进展自然接上；第一步做什么
（最多 3 条。依据 Notion「下一步 / 进行中 / 待验证」和各项目昨日进展；Notion 里优先级高、截止近的优先）

## ⏰ 3 天内到期
- 任务名（项目）— 截止 MM-DD HH:MM，当前状态

## 📈 昨日进展
- **项目**：1–3 行，合并重复的动态，保留关键数字和提交

## 🛠 需要你处理的会话
- 项目 · 会话名 — 状态；`claude attach <短 id>`（远程：先 ssh 到服务器）

## 💡 建议（可选）
- Notion 缺字段、过期未更新、状态与实际进展不符等，写成可执行的建议（不要直接改）
```

## 4. 之后
这个会话会被我用来追问（「展开说说某个项目」「把第 2 条派给某个项目」）。追问时按 CLAUDE.md 的主控约定处理：派活、转达、写 Notion 都遵守原有的规则。
